04

Interpretation

  • Removing the model name after product filtering is the main retrieval improvement; aspect boosting adds further early-ranking gains.
  • The latest model improves P@10 by 0.0875 and nDCG@10 by 0.0932 over configuration 7; per-query nDCG records 34 wins, 0 ties and 6 losses.
  • Configurations 5/6 and 7/8 respectively share the same Top100 membership. Reordering alone therefore leaves Recall@100 unchanged.
  • Legacy reranking does not show a stable gain. With model names retained, RRF also trails dense-only early ranking; fusion is not universally better.

07

How the latest model was trained

100 new queries × 20 fixed retrieval candidates = 2,000 judgments. The 16 training products, query texts, chunks, source reviews and exact text are disjoint from evaluation40. The 40 evaluation queries were not used for this fit or parameter selection.

MiniLM remains frozen; only a ridge-regularized linear fusion layer is fitted. Five-fold product-group validation selects among 32 settings, keeping each product entirely within one fold. The selected seven standardized features are raw MiniLM score, semantic reciprocal rank, retrieval reciprocal rank, aspect coverage, log keyword count, keyword density and log text length. The ridge penalty is 100; targets are query-centered grades 0–3.

score = Σ wᵢ × zᵢ   ·   zᵢ = (xᵢ − mean(xᵢ)) / max(std(xᵢ), 10⁻⁶)

Nested product-group validation within training100 gives P@10=0.8450, MRR@10=0.9783 and nDCG@10=0.8635. These are internal training-set validation values, separate from the 40-query report.

The previous model trained on evaluation40 scored nDCG=0.8628 on those queries; the new training100 model scores 0.8573, slightly lower, while P@10 increases from 0.8875 to 0.8925. The earlier model used these queries in fitting, so this is not a comparison of independent generalization. It is context, not a ninth configuration.

08

Evaluation protocol and scope

Full index and candidates

Shared index of 459,418 chunks; effective depth 300 per channel; retain 100 per product and at most one chunk per review. Configurations 7/8 merge products into a global Top100. Legacy configurations 6/7 rerank 100 candidates; configuration 8 reranks 20. The replacement changes semantic query handling, fusion and window together, so its entire gain cannot be attributed to learned coefficients alone.

Common judgments

Original 2,564 pairs plus 62 earlier and six later Top10 supplements: 2,632 judgments. All eight systems and all four metrics share these qrels. Every Top10 result is judged; ranks 11–100 do not require exhaustive labeling. Recall credits known positive hits only. Supplements were not used to train the new model.

Four metrics

P@10: relevant results in the first 10 / 10. Recall@100: known positives found in the first 100 / all known positives for that query. MRR@10: reciprocal rank of the first relevant result in the first 10. Grades ≥2 are binary relevant.

nDCG@10 uses linear gains 0, 1, 2, 3: DCG = Σ grade / log₂(rank+1). IDCG uses the ten best judgments for that query. Metrics are computed per query then macro-averaged over 40 queries.

Result provenance

Saved full-index Top100 runs and frozen MiniLM logits are reused. The latest reranking replaces configuration 8 and all eight metric sets are recomputed. Report preparation makes no retrieval or rewrite API calls. All 1,280 per-query metric values pass independent arithmetic checks.

This is cumulative ablation, not a factorial experiment; configurations 1/2 are parallel baselines. Stage 7 bundles rewriting and multi-product parsing. Recall uses incomplete pooled judgments, not exhaustive corpus relevance. The common qrels differ from historical reports, so their Recall values cannot be carried over. Evaluation40 influenced earlier development and is not a historically untouched blind test. Metrics measure evidence retrieval, not generated answer quality.
